# CLAUDE.md

Памятка для Claude Code при работе с этим репозиторием.

## Что это

«Личное инфо» — база учебных конспектов. Дерево **Глава → Тема → Ветка →
Карточка**, содержимое карточки — **блоки** с цветной меткой термина, текстом и
фотографиями. Работает **только как Telegram Mini App** в боте `@alima_dem_bot`: вне
Telegram показывается экран со ссылкой на бота.

Интерфейс полностью на русском. Вся новая текстовка — тоже на русском.

## Команды

```bash
npm run dev      # разработка на :5173
npm run build    # tsc -b + vite build — гонять перед завершением задачи
npm run lint     # oxlint

SUPABASE_SERVICE_ROLE_KEY=… node scripts/backup.mjs   # копия таблиц и картинок, см. docs/SETUP.md
```

Node ставится через nvm: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"`.
Без этого `node` не найдётся в PATH.

## Границы, которые стоит держать

- **Все обращения к базе живут в `src/lib/api.ts`.** Компоненты не вызывают
  `supabase` напрямую — исключение только `AuthContext` для сессии. Чтение
  таблиц целиком — через `fetchAllPages` (PostgREST отдаёт максимум 1000 строк),
  запись — только через `write()`: он держит сессию живой, повторяет при обрыве
  связи и отдаёт текст ошибки по-русски. После записи звать `invalidateData`,
  иначе service worker покажет прошлую версию.
- **Чтение не тянет TipTap.** `NoteView` рисует документ через `lib/render.tsx`;
  TipTap живёт только в `BlockEditor` → `NoteEditor` → `tiptap-config.ts` /
  `editor.ts`, и этот кусок грузится лениво. Импорт любого из этих файлов из
  пути чтения вернёт 130 КБ gzip в основной бандл. Что нужно документу без
  редактора (`contentToText`, `extractTerms`, `imageUrls`) — в `lib/doc.ts`.
  Добавили расширение редактору — добавьте ветку в `render.tsx`.
- **Цвета не хардкодятся.** Только CSS-переменные (`var(--fg)`, `var(--accent)`,
  `var(--danger)`, `var(--term-red-bg)` и так далее), иначе сломается одна из
  трёх тем. Палитры тем — в `src/index.css`, блоки `[data-theme="…"]`.
- **Подписи уровней — в `KIND_META`** (`src/lib/types.ts`), смысл цветных меток —
  в `TERM_LABELS` там же. Не дублировать строки по компонентам.
- **Дерево грузится целиком одним запросом** и живёт в `TreeContext`. Не
  добавлять точечные запросы за отдельными узлами — берите из `byId`.
- **Правки дерева идут через `TreeContext`.** `moveNode` оптимистичный —
  локальное состояние меняется до сети; создание, правка и удаление ждут ответ.
  Новые мутации добавлять туда же, а не в компоненты.
- **Размер текста — это `zoom` на содержимом**, переменная `--app-zoom`
  (`SCALES` в `SettingsContext`). Отдельно от него — размер и межстрочное
  самого конспекта: `--note-size` / `--note-leading` (`NOTE_SIZES`,
  `NOTE_LEADINGS` там же), их читает `.prose-note` в `index.css`. Любое новое
  полноэкранное окно рендерить порталом в `body` и вешать `app-zoom` на саму
  панель, иначе при крупном шрифте окно съедет. Высоты вида `92vh` внутри таких панелей делить на `var(--app-zoom)`.
  Шапка, шторка и полоса состояния сидят на `shell-zoom` (`--shell-zoom`): на
  экранах уже 640px он равен 1, иначе строка с иконками не помещалась и
  страница расширялась. Отступ «под шапкой» — класс `under-header`, он уже
  учитывает оба масштаба. Поля ввода на телефоне держатся не мельче 16px на
  экране (иначе Safari приближает страницу при фокусе), поэтому их `font-size`
  делится на `--app-zoom` — блок `hover: none` в `index.css`.
- **Офлайн держится на `public/sw.js`** — правила кэширования только там, при
  изменении поднимать `VERSION`, иначе у людей останется старый кэш. Service
  worker регистрируется только в собранной версии (`import.meta.env.PROD`).
  Данные он отдаёт «сохранённое сразу, свежее в фоне» и шлёт `DATA_UPDATED`,
  когда свежее отличается; приложение разговаривает с ним только через
  `lib/sw-client.ts` (`askWorker`, `invalidateData`, `onDataUpdated`). Любое
  кэшируемое чтение нуждается в подписке на `onDataUpdated`, иначе страница
  будет показывать прошлую версию до второй перезагрузки: так уже случилось с
  правами редактора, которые выдаются не из этого браузера. Сейчас подписаны
  дерево, блоки, настройки и `AuthContext`.
  Копию сохранённого ответа для сравнения снимать **до** того, как он уйдёт в
  `respondWith`: после этого его тело считается использованным и `clone()`
  бросает ошибку — кэш тогда не обновляется вообще.
- **Перечитывание при возврате во вкладку — через `lib/visibility.ts`.** Один
  общий слушатель (`visibilitychange` + `pageshow` ради bfcache), пауза
  `QUIET_MS`, отсчёт от загрузки. Подписаны `TreeContext` и `BlockList`; блоки
  не перечитываются при открытом редакторе — иначе текст подменится под руками.
  Свои `visibilitychange` по компонентам не заводить.
- **Картинки и внешние стили — с `crossorigin`.** Без него ответ «непрозрачный»
  и в кэш не попадает. Supabase Storage, Google Fonts и telegram.org отдают
  `Access-Control-Allow-Origin: *`, проверено.
- **Ошибки записи показываются на месте** — `ErrorNote` под кнопкой, текст
  остаётся в форме. Не `window.alert`: в Telegram он может не показаться вовсе.
- **Блок сохраняется в фоне.** `BlockEditor` по «Сохранить» отдаёт в
  `BlockList` локальную версию и `commit`; редактор закрывается сразу, блок
  висит с пометкой «Сохраняется…», при ошибке — `ErrorNote` с «Открыть и
  повторить». Черновик стирается только после успешной записи.

## Данные

`nodes` — самоссылающееся дерево (`parent_id`), уровень задаётся полем `kind`
(`chapter | topic | branch | card`). Глубина технически не ограничена: пятый
уровень не потребует миграции.

`blocks` — содержимое карточки, по строке на термин. Отдельная таблица выбрана
осознанно: ключевой сценарий — «дополнить именно ТПО», то есть правка ровно
одного блока, с поблочной историей в `block_revisions`.

`block_revisions` без внешнего ключа на `blocks` — намеренно: триггеры
`blocks_before_delete` и `nodes_before_delete` пишут туда последнюю версию
(`op = 'delete'`, `path` до карточки), и каскад не должен её уносить.

Роли: **читатель** — любой, кто открыл бота (строка в `telegram_accounts`, функция
`is_reader()`), их сколько угодно; **редактор** ещё создаёт, правит и удаляет; **владелец**
ещё даёт и снимает права. Роль лежит в `editors.role`; нет строки — читатель.

Управляют правами только функции `make_editor`, `remove_editor`, `create_editor_invite`,
`list_people` (`security definer`, проверяют `is_owner()`). Владельца через них не убрать.
Поменять `role` через таблицу нельзя: политика `editors_self` даёт только читать свою строку.

`telegram_accounts` заполняет только функция `supabase/functions/telegram-auth`: она
проверяет подпись `initData` токеном бота и выдаёт сессию Supabase. Чтение требует
`is_reader()`, а не просто вход: иначе прочитал бы любой, кто зарегистрировался через API.

`editor_invites` — одноразовые ссылки `t.me/alima_dem_bot?startapp=код` для тех, кто ещё
не открывал бота. Живут 7 дней. RLS включён, политик нет. Код применяет `AuthContext` через
`claim_editor(p_code)`. Ссылку на нового владельца создаёт только SQL (`role = 'owner'`).

`editor_invite` (одна строка, общая фраза) работает, только пока в базе нет ни
одного владельца: это запуск с нуля.

Колонка `role` добавляется один раз, и все прежние редакторы становятся
владельцами именно в этот момент. Не выносить `update` из этой ветки: повторный
запуск схемы повысил бы всех приглашённых.

Бакет `notes` остаётся публичным: фото открываются по адресу со случайным именем, а сами
адреса лежат в закрытых блоках. Списка файлов снаружи получить нельзя, но у кого есть прямой
адрес фото, тот его откроет: это сознательное упрощение.

Схема целиком в `supabase/schema.sql`, она идемпотентна (`create if not exists`,
`create or replace`, `alter … if exists`) — её же прогоняют повторно, чтобы
обновить живую базу. Демо-данные в `supabase/seed.sql`. Локально Postgres нет;
схему, функции и RLS можно прогнать на `@electric-sql/pglite` (npm, настоящий
Postgres в процессе), подложив заглушки `auth.users`, `auth.uid()`, `storage.*` и роли
`anon`, `authenticated`.

При изменении схемы проверяйте заодно:
- политики RLS (читает `is_reader()`, пишет `is_editor()`);
- функцию `search_all` — она объединяет поиск по узлам и по блокам; если
  меняется набор колонок результата, нужен `drop function` перед `create`;
- генерируемые `search_vector` — в них только immutable-выражения;
- триггеры `touch_node` и `bump_node_from_block` — они нарочно не трогают
  `updated_at` при смене одного лишь `position`;
- фронтенд должен работать и со старой схемой до её обновления (например,
  `search_all` без `color`). Исключение — вход: без функции `telegram-auth` приложение
  не откроется, поэтому при развёртывании с нуля сначала функция и схема, потом фронтенд.

## Редактор

TipTap 3, только в ленивом куске `BlockEditor`. Набор расширений —
`src/lib/tiptap-config.ts`; чтение повторяет его разметку в `src/lib/render.tsx`,
чтобы вёрстка совпадала. Кегль и межстрочное задаёт читательница в настройках
(`--note-size`, по умолчанию 16px и плотные строки — «как в Telegram»); в
редакторе на 1px мельче (`index.css`, «Редактор и чтение»). Не выравнивать.

Своя метка термина — `TermMark` в `src/lib/editor.ts`: рисуется как
`<span class="term" data-color="…">`, цвет берётся из CSS-переменных.
Подсказка (`note`) показывается списком под блоком (`NoteView`).

При сохранении блока обязательно писать и `content` (JSON), и `content_text`
(через `contentToText` из `doc.ts`) — иначе блок не попадёт в поиск.

Новый блок до первого «Сохранить» в базе не существует (`editing === 'new'` в
`BlockList`). Черновики — `lib/drafts.ts`, чистятся при сохранении и по
«Не сохранять». Картинки перед загрузкой уменьшает `lib/image.ts`.

## Telegram

Обёртка в `src/lib/telegram.ts`, в обычном браузере все вызовы — заглушки.
`bindTelegramBack` возвращает функцию отписки и вызывается внутри `useEffect`.
Не переименовывать в `useTelegramBack`: это не хук.

Пока кнопка «назад» скрыта, на её месте у Telegram стоит «Закрыть», и экран
закрывается вместе с приложением. Поэтому: куда ведёт страница — `bindTelegramBack`
(разделы — `NodePage`, остальное кроме главной — `AppShell`); любое новое окно
поверх страницы — `useTelegramOverlay(open, onClose)`. `Modal`, `Lightbox`,
`SearchPalette`, шторка и редактор блока уже подключены. Внешние ссылки `initTelegram`
сам отправляет через `openLink`. `window.prompt`/`alert`/`confirm` не использовать.

Первая тема выбирается как на сайте, по системе, а не по `colorScheme` Telegram:
приложение должно выглядеть одинаково. Цветами и шапкой занимается
`syncTelegramChrome`; своих стилей под Telegram нет — класс `is-telegram` ни к чему
не привязан, и так задумано.

Вход делает `AuthContext` без участия человека: `TelegramGate` смонтирован выше всего, что
читает базу, иначе пустые ответы до входа осели бы в офлайн-кэше. Почты и пароля в приложении
нет. Функция разворачивается с `--no-verify-jwt`: человек приходит без сессии, а publishable-
ключ не JWT. Токен бота — только секрет `TELEGRAM_BOT_TOKEN` в Supabase, в репозиторий не класть.

`inTelegram()` смотрит на `initData` и `platform`: скрипт SDK подключён всегда,
и в браузере он тоже создаёт `window.Telegram.WebApp` — с пустым `initData` и
`platform = 'unknown'`. Проверять одно лишь наличие объекта нельзя.

Ссылка на сайт, открытая из чата, попадает не в Mini App, а во встроенный браузер
Telegram — `inTelegram()` там ложно, и человек увидит экран со ссылкой на бота. На iPhone этот браузер навязывает странице
свой размер шрифта: `* { -webkit-text-size-adjust: N% !important }`. Отменяет
это правило `html, body, body *` в `index.css`; без `!important` или с
селектором проще `body *` оно проиграет, и страница снова откроется
«приближенной». Подробности — `docs/ARCHITECTURE.md`, «Чужой размер шрифта».

## Проверка изменений

Прогонять `npm run build` — она включает проверку типов.

Офлайн и установку в `npm run dev` не проверить: service worker там намеренно не
регистрируется. Нужно собрать и поднять статику поверх `dist`:

```bash
npm run build && (cd dist && python3 -m http.server 4173)
```

Для визуальной проверки удобен headless-снимок:

```bash
npm run dev &
cd ~ && mkdir -p shots && cd shots
chromium --headless --disable-gpu --no-sandbox --window-size=1280,1000 \
  --virtual-time-budget=8000 --screenshot=out.png http://localhost:5173/
```

Chromium здесь из snap: он не пишет в `/tmp` и в скрытые папки, только в обычные
каталоги внутри `$HOME`.

## Известные упрощения

Сознательно оставлено как есть — список с подробностями в
`docs/ARCHITECTURE.md`, раздел «Что осталось недоделанным»:

- открытые страницы обновляются сами, но новые карточки попадают в офлайн-кэш
  только кнопкой «Скачать» или когда их откроют;
- сворачивание блоков помнит один общий выбор, а не состояние каждой карточки;
- поиск по тексту офлайн не работает: `search_all` — это RPC, то есть POST;
- история правок пишется, но в интерфейсе не показывается — только SQL;
- картинки, убранные из текста, остаются в хранилище;
- вопрос о несохранённом задаётся при смене блока и по «Отмена», но не при
  переходе по ссылке — там выручает черновик.

## Чего не делать

- Не класть в приложение ключ `service_role` — только `anon`. Он живёт в функции
  `telegram-auth` (подставляет Supabase) и передаётся бэкапу при запуске.
- Не выдавать права редактора за один факт входа и не проверять код приглашения на
  клиенте: сверяет его только `claim_editor` в базе. Показ раздела владельца по `isOwner` и
  экран `TelegramGate` — лишь удобство: доступ проверяет база.
- Не убирать inline-скрипт выбора темы из `index.html`: без него при загрузке
  мигает белый экран.
- Не добавлять зависимость ради одной функции: набор намеренно небольшой.
- Не импортировать TipTap (`@tiptap/*`, `editor.ts`, `tiptap-config.ts`,
  `NoteEditor`) нигде, кроме `BlockEditor` и его потомков.
- Не делать `insert` без клиентского `id` там, где возможен повтор запроса —
  `write()` повторяет, и без `upsert` появятся дубликаты.
