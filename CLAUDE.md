# CLAUDE.md

Памятка для Claude Code при работе с этим репозиторием.

## Что это

«Личное инфо» — база учебных конспектов. Дерево **Глава → Тема → Ветка →
Карточка**, содержимое карточки — **блоки** с цветной меткой термина, текстом и
фотографиями. Один код работает и как сайт, и как Telegram Mini App.

Интерфейс полностью на русском. Вся новая текстовка — тоже на русском.

## Команды

```bash
npm run dev      # разработка на :5173
npm run build    # tsc -b + vite build — гонять перед завершением задачи
npm run lint     # oxlint
```

Node ставится через nvm: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"`.
Без этого `node` не найдётся в PATH.

## Границы, которые стоит держать

- **Все обращения к базе живут в `src/lib/api.ts`.** Компоненты не вызывают
  `supabase` напрямую — исключение только `AuthContext` для сессии.
- **Цвета не хардкодятся.** Только CSS-переменные (`var(--fg)`, `var(--accent)`,
  `var(--term-red-bg)` и так далее), иначе сломается одна из трёх тем.
  Палитры тем — в `src/index.css`, блоки `[data-theme="…"]`.
- **Подписи уровней — в `KIND_META`** (`src/lib/types.ts`), смысл цветных меток —
  в `TERM_LABELS` там же. Не дублировать строки по компонентам.
- **Дерево грузится целиком одним запросом** и живёт в `TreeContext`. Не
  добавлять точечные запросы за отдельными узлами — берите из `byId`.
- **Правки дерева идут через `TreeContext`.** `moveNode` оптимистичный —
  локальное состояние меняется до сети; создание, правка и удаление ждут ответ.
  Новые мутации добавлять туда же, а не в компоненты.
- **Размер текста — это `zoom` на содержимом**, переменная `--app-zoom`
  (`SCALES` в `SettingsContext`). Любое новое полноэкранное окно рендерить
  порталом в `body` и вешать `app-zoom` на саму панель, иначе при крупном шрифте
  окно съедет. Высоты вида `92vh` внутри таких панелей делить на `var(--app-zoom)`.
- **Офлайн держится на `public/sw.js`** — правила кэширования только там, при
  изменении поднимать `VERSION`, иначе у людей останется старый кэш. Service
  worker регистрируется только в собранной версии (`import.meta.env.PROD`).

## Данные

`nodes` — самоссылающееся дерево (`parent_id`), уровень задаётся полем `kind`
(`chapter | topic | branch | card`). Глубина технически не ограничена: пятый
уровень не потребует миграции.

`blocks` — содержимое карточки, по строке на термин. Отдельная таблица выбрана
осознанно: ключевой сценарий — «дополнить именно ТПО», то есть правка ровно
одного блока, с поблочной историей в `block_revisions`.

Схема целиком в `supabase/schema.sql`, она идемпотентна (`create if not exists`,
`create or replace`) — можно выполнять повторно. Демо-данные в `supabase/seed.sql`.

При изменении схемы проверяйте заодно:
- политики RLS (читают все, пишет `is_editor()`);
- функцию `search_all` — она объединяет поиск по узлам и по блокам;
- генерируемые `search_vector` — в них только immutable-выражения.

## Редактор

TipTap 3. Общий набор расширений — `src/lib/tiptap-config.ts`, он используется и
для чтения (`NoteView`), и для правки (`NoteEditor`), чтобы вёрстка совпадала.

Своя метка термина — `TermMark` в `src/lib/editor.ts`: рисуется как
`<span class="term" data-color="…">`, цвет берётся из CSS-переменных.

При сохранении блока обязательно писать и `content` (JSON), и `content_text`
(через `contentToText`) — иначе блок не попадёт в поиск.

## Telegram

Обёртка в `src/lib/telegram.ts`, в обычном браузере все вызовы — заглушки.
`bindTelegramBack` возвращает функцию отписки и вызывается внутри `useEffect`.
Не переименовывать в `useTelegramBack`: это не хук.

## Проверка изменений

Прогонять `npm run build` — она включает проверку типов.

Офлайн и установку в `npm run dev` не проверить: service worker там намеренно не
регистрируется. Нужно собрать и поднять статику поверх `dist`:

```bash
npm run build && (cd dist && python3 -m http.server 4173)
```

Для визуальной проверки удобен headless-снимок:

```bash
npm run dev &
cd ~ && mkdir -p shots && cd shots
chromium --headless --disable-gpu --no-sandbox --window-size=1280,1000 \
  --virtual-time-budget=8000 --screenshot=out.png http://localhost:5173/
```

Chromium здесь из snap: он не пишет в `/tmp` и в скрытые папки, только в обычные
каталоги внутри `$HOME`.

## Чего не делать

- Не класть в приложение ключ `service_role` — только `anon`.
- Не убирать inline-скрипт выбора темы из `index.html`: без него при загрузке
  мигает белый экран.
- Не добавлять зависимость ради одной функции: набор намеренно небольшой.
