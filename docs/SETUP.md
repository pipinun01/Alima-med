# Установка с нуля

Пошагово: от пустого места до работающего Telegram Mini App.
Ничего платного не требуется — хватает бесплатных тарифов Supabase и Vercel.

---

## 1. Локальный запуск

Нужен Node 20 или новее.

```bash
cd lichnoe-info
npm install
npm run dev
```

Откроется `http://localhost:5173`. Пока не заданы ключи, приложение показывает
экран настройки — это ожидаемо.

---

## 2. Supabase

### 2.1 Создать проект

1. Зарегистрироваться на [supabase.com](https://supabase.com), создать организацию.
2. **New project**: имя любое, регион — ближайший (для СНГ обычно Frankfurt).
3. Пароль базы сохранить в надёжном месте — он понадобится, если полезете в БД напрямую.
4. Подождать 1–2 минуты, пока проект поднимется.

### 2.2 Выполнить схему

1. Слева **SQL Editor** → **New query**.
2. Скопировать целиком содержимое `supabase/schema.sql`, вставить, нажать **Run**.
3. Должно быть `Success. No rows returned`.

Схема создаёт таблицы `nodes`, `blocks`, `block_revisions`, `editors`,
`app_settings`, функции поиска, политики доступа и бакет для картинок.

### 2.2.1 Обновление уже развёрнутой базы

Тот же файл — тот же способ. `schema.sql` идемпотентный: его можно запускать
сколько угодно раз, он сам добавит недостающие колонки, пересоздаст функции и
триггеры и ничего не удалит. **После обновления кода из репозитория прогоняйте
его снова** — иначе часть обещаний интерфейса (история при удалении, цвет
метки в поиске, защита от циклов) останется только обещанием.

### 2.3 Демо-данные (по желанию)

Тем же способом выполнить `supabase/seed.sql` — появится глава «Гинекология»
с темами, ветками и заполненной карточкой «ТПО, ТГ». Всё это потом удаляется
прямо из интерфейса.

### 2.4 Забрать URL и ключ

Supabase переделал этот раздел, и в разных проектах он выглядит по-разному.
Ниже — самый короткий путь и два запасных.

#### Способ 1: кнопка Connect (работает всегда)

Вверху страницы проекта, рядом с его названием, есть кнопка **Connect**. Она
открывает окно, где уже собраны и адрес, и ключ.

1. Нажать **Connect**.
2. Выбрать вкладку **App Frameworks**.
3. Framework — **React**, Using — **Vite**.
4. Supabase покажет готовый блок вида:

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=...
```

Скопировать целиком — это ровно то, что нужно вставить в `.env.local`.

#### Способ 2: по разделам меню

Адрес и ключ лежат в разных местах:

- **Адрес проекта** — шестерёнка **Project Settings** → **Data API** →
  поле **Project URL**. Выглядит как `https://xxxxxxxx.supabase.co`.
- **Ключ** — **Project Settings** → **API Keys**. Там две вкладки:
  - **Publishable key** — новый ключ, начинается с `sb_publishable_`.
    Если его ещё нет, нажать **Create new API keys**.
  - **Legacy API Keys** — старый ключ `anon` `public`, длинная строка,
    начинается с `eyJ`. У проектов, созданных раньше, обычно есть только он.

Годится любой из двух — берите тот, который видите.

#### Способ 3: собрать адрес вручную

Адрес проекта всегда складывается из его идентификатора, а идентификатор виден
прямо в адресной строке браузера:

```
https://supabase.com/dashboard/project/abcdefghijklmnop
                                       ^^^^^^^^^^^^^^^^ это и есть ref
→ VITE_SUPABASE_URL = https://abcdefghijklmnop.supabase.co
```

### 2.5 Вписать в файл

```bash
cp .env.example .env.local
```

Открыть `.env.local` и оставить две строки — адрес и **один** ключ:

```bash
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co

# если ключ начинается с sb_publishable_
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxx

# если ключ начинается с eyJ — использовать эту строку вместо предыдущей
# VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

Приложение понимает оба имени, так что достаточно одного.

После правки **перезапустить** `npm run dev` — переменные читаются только при
старте.

Файл `.env.local` в git не попадает.

> Этот ключ публичный, его видно в браузере — так и задумано. Данные защищает не
> он, а Row Level Security: без записи в таблице `editors` изменить ничего
> нельзя. А вот **secret key** (`sb_secret_…`) и **service_role** в приложение
> класть нельзя никогда — они обходят все проверки.

## 3. Вход через Telegram и роли

Приложение работает только в боте. Читает любой, кто его открыл, а править может
тот, кому дал права владелец.

| Роль | Читает | Создаёт, правит, удаляет | Даёт и снимает права |
|---|---|---|---|
| Читатель | да | нет | нет |
| Редактор | да | да | нет |
| Владелец | да | да | да |

### 3.1 Функция входа

Функция `telegram-auth` проверяет подпись Telegram и выдаёт сессию:

```bash
supabase login
supabase functions deploy telegram-auth --no-verify-jwt --project-ref <ref>
supabase secrets set --project-ref <ref> TELEGRAM_BOT_TOKEN=<токен бота>
```

Без `--no-verify-jwt` шлюз отклонит вход: человек приходит ещё без сессии.

### 3.2 Первый владелец

На пустой базе выдать права ещё некому, поэтому первого владельца создаёт SQL. В SQL
Editor:

```sql
insert into editor_invites (role) values ('owner') returning code;
```

Полученный код подставьте в ссылку и откройте её в Telegram:
`https://t.me/<бот>?startapp=<код>`. Ссылка срабатывает один раз и живёт 7 дней. Так же
создаётся и второй владелец.

Снять владельца можно только в SQL:

```sql
update editors set role = 'editor'
where user_id = (select user_id from telegram_accounts where username = 'имя');
```

### 3.3 Переход с входа по почте

Новый вход создаёт новый аккаунт, поэтому прежним владельцам нужны ссылки из 3.2. Когда
новые владельцы вошли, старые почтовые аккаунты лишают прав:

```sql
delete from editors where user_id not in (select user_id from telegram_accounts);
```

Конспекты и история правок при этом не меняются.

### 3.4 Остальные

Владелец: **профиль → Люди**. Кто уже открывал бота, того можно сделать редактором
кнопкой. Кто не открывал, тому отправляется одноразовая ссылка. Там же снимаются права.

## 4. Деплой на Vercel

1. Залить репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выбрать репозиторий.
3. Framework Vercel определит сам (Vite). Настройки по умолчанию подходят.
4. **Environment Variables** — добавить те же две переменные, что в
   `.env.local`: `VITE_SUPABASE_URL` и ключ — `VITE_SUPABASE_PUBLISHABLE_KEY`
   или `VITE_SUPABASE_ANON_KEY`, смотря какой у вас.
5. **Deploy**.

### Важно: перезапись маршрутов

Приложение одностраничное, поэтому прямая ссылка вида `/n/<id>` должна отдавать
`index.html`. В репозитории для этого лежит `vercel.json`. Если разворачиваете
где-то ещё — настройте тот же fallback.

### Адрес сайта в Supabase

Для самого входа это не нужно: приложение логинится по почте и паролю без
перенаправлений. Но «Забыли пароль?» и смена почты работают через письма, и
ссылки в них ведут на сайт — без этих настроек (значение по умолчанию
`http://localhost:3000`) они поведут в никуда.

**Authentication → URL Configuration**:

- **Site URL** — адрес сайта, например `https://alima-med.vercel.app`
- **Redirect URLs** — добавить два шаблона:
  - `https://alima-med.vercel.app/**`
  - `http://localhost:5173/**` — чтобы то же работало при локальной разработке

`**` подставляет любой путь — это синтаксис Supabase.

## 5. Приложение и офлайн

Отдельной сборки не нужно: сайт сам объявляет себя приложением.

- `public/manifest.webmanifest` — название, цвета, иконки.
- `public/sw.js` — service worker: держит оболочку, ответы на чтение и картинки.
- Иконки `icon-192.png`, `icon-512.png`, `icon-maskable.png`,
  `apple-touch-icon.png` лежат в `public/`.

Условия, без которых установка и офлайн не заработают:

1. **HTTPS.** На Vercel он есть по умолчанию; локально — только `localhost`.
2. **Собранная версия.** В `npm run dev` service worker не регистрируется
   намеренно, иначе кэш мешал бы правкам. Проверять так:

   ```bash
   npm run build
   cd dist && python3 -m http.server 4173
   ```

3. **Файл `sw.js` должен отдаваться с корня** — `https://сайт/sw.js`. При
   раздаче из подпапки офлайн работать не будет.

Пользователю остаётся открыть настройки (значок с ползунками в шапке) и нажать
«Установить приложение», а затем «Скачать … карточек», чтобы конспекты читались
без сети. Подробности для неё — в [CONTENT-GUIDE.md](CONTENT-GUIDE.md).

### Обновление правил кэширования

Если правите `public/sw.js`, поднимите `VERSION` в начале файла. Иначе у тех,
кто уже открывал сайт, останутся старые кэши.

## 6. Telegram Mini App

### 6.1 Создать бота

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → задать имя и username.
2. Сохранить токен: он нужен функции входа (раздел 3.1). В репозиторий его не класть.

### 6.2 Включить Mini App

`/mybots` → выбрать бота → **Bot Settings → Configure Mini App → Enable Mini App** →
адрес с Vercel, обязательно `https://`. Без этого не работают ссылки `?startapp=код`.

### 6.3 Кнопка в меню бота

`/mybots` → выбрать бота → **Bot Settings → Menu Button → Configure menu button**
→ вставить тот же URL и подпись, например «Конспекты».

### 6.4 Что уже сделано в коде

- SDK Telegram подключён в `index.html`.
- При запуске вызываются `ready()` и `expand()`, отключается вертикальный свайп,
  чтобы шторка не закрывалась при прокрутке конспекта.
- Цвет шапки, фона и нижней панели Telegram подстраивается под выбранную тему.
- Системная кнопка «назад» закрывает открытое окно, поиск, шторку или редактор, а
  если их нет — ведёт на родительский раздел. На главной на её месте «Закрыть».
- Внешние ссылки открываются через Telegram (`openLink`).
- При несохранённом тексте Telegram спрашивает подтверждение перед закрытием.
- В настройках есть «Добавить на экран» (Telegram 8.0+).
- Хаптика на переключениях и сохранении.
- Учитываются безопасные зоны (`env(safe-area-inset-*)`).

### 6.5 Проверка

Открыть бота в Telegram → кнопка меню → приложение. На десктопном Telegram
удобно отлаживать через `Ctrl+Shift+I`.

Без телефона логику можно проверить эмуляцией: `telegram-web-app.js` сам читает
параметры из адреса, поэтому страница с хэшем
`#tgWebAppData=…&tgWebAppVersion=9.1&tgWebAppPlatform=ios` работает как Mini App,
а команды приложения видно, если заранее определить
`window.TelegramWebviewProxy = { postEvent(type, data) {…} }`. Смена только хэша
страницу не перезагружает — SDK при этом останется в режиме браузера. Настоящий вход так не
пройдёт: подпись не сойдётся, поэтому ответы функции и базы подменяются.

### 6.6 Настройки хранятся на устройстве

Тему и размер текста каждый выбирает у себя. Роль, общий фон и конспекты лежат в базе и
совпадают на всех устройствах.

### 6.7 Ссылка из чата — это не Mini App

Если адрес сайта просто прислать сообщением и нажать на него, Telegram откроет его в своём
встроенном браузере. Там приложение покажет экран со ссылкой на бота. Присылать нужно
ссылку на бота: `https://t.me/<бот>`.

## 8. Бэкап

Всё, что написано, живёт в одном проекте Supabase. База закрыта, поэтому нужен служебный
ключ (**Settings → API Keys**). Его передают только при запуске и никуда не сохраняют:

```bash
SUPABASE_SERVICE_ROLE_KEY=… node scripts/backup.mjs              # в ~/lichnoe-info-backups/<дата>
SUPABASE_SERVICE_ROLE_KEY=… node scripts/backup.mjs /куда/угодно
```

Складывает он два каталога:

- `data/` — таблицы в JSON: `nodes`, `blocks`, `app_settings`, `block_revisions`, `editors`,
  `telegram_accounts`;
- `storage/` — все фотографии из бакета `notes`, пути совпадают с адресами в базе.

Восстановление: прогнать `schema.sql` в новом проекте, залить JSON обратно и
положить файлы в бакет `notes` с теми же путями.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Экран «Осталось подключить базу» | Нет `.env.local`, опечатка в имени переменной или не перезапущен `npm run dev` |
| В `.env.local` вписан ключ, но экран тот же | Имя переменной должно быть ровно `VITE_SUPABASE_PUBLISHABLE_KEY` или `VITE_SUPABASE_ANON_KEY`, с префиксом `VITE_` |
| Вошёл, но кнопок редактирования нет | UID не добавлен в `editors` — ввести код приглашения в профиле (`/profile`) или добавить строку руками |
| «Код приглашения не задан в базе» | Не выполнен `update editor_invite set code = '…'` |
| «Код не подошёл» | Фраза набрана не целиком или с опечаткой; сверить с тем, что лежит в `editor_invite` |
| «Регистрация выключена в Supabase» | **Authentication → Providers → Email**, включить `Enable sign up` |
| «Слишком много писем за раз» | Лимит встроенного почтовика Supabase — пара писем в час. Подождать, снять `Confirm email` или подключить свой SMTP. Если аккаунт уже заведён, регистрироваться заново не нужно — нужна вкладка «Вход» |
| Права выдали через SQL, а кнопок всё нет | Ответ «не редактор» лежал в офлайн-кэше. Приложение перечитывает права само, как только worker увидит изменение; не дождались — перезагрузить страницу |
| `new row violates row-level security policy` | То же самое: аккаунт не редактор |
| Фото не загружаются | Не выполнена часть схемы про `storage.buckets` / политики |
| Поиск ничего не находит | Не выполнен `schema.sql` целиком: нет функции `search_all` |
| Прямая ссылка на карточку даёт 404 | На хостинге не настроен SPA-fallback на `index.html` |
| В Telegram белый экран | URL должен быть `https://`, без самоподписанного сертификата |
| На iPhone ссылка из чата Telegram открывается «приближенной», страницу приходится сводить пальцами | Встроенный браузер Telegram навязывал свой размер шрифта (меню «Аа»). Приложение это отменяет — обновите код и разверните заново. Если правило `html, body, body *` из `index.css` убрали, верните его |
| На телефоне страница приближается при нажатии на поле ввода и так и остаётся | Поле на экране мельче 16px. В `index.css` размер полей делится на `--app-zoom`; новое поле со своим `font-size` должно следовать тому же правилу |
| Нет кнопки «Добавить на экран» | Эта версия Telegram не умеет. Поможет обновление |
| «Не получилось войти» в боте | Не развёрнута функция `telegram-auth`, забыт `--no-verify-jwt` или неверен секрет `TELEGRAM_BOT_TOKEN` |
| Офлайн ничего не открывается | Сайт ни разу не открывали после сборки с `sw.js`, либо не нажимали «Скачать» |
| После правок видна старая версия | Не поднят `VERSION` в `public/sw.js` |
| Новые главы и карточки не видны ни после перезагрузки — помогает только очистка данных сайта | Сравнение в `sw.js` падало, и сохранённая копия не обновлялась никогда. Чинено в `VERSION = v4`: обновите код и разверните заново, у людей всё встанет на место при следующем открытии |
| «Не сохранилось: нет связи с сервером» | Сеть. Приложение само повторило запрос трижды; текст остался в редакторе и в черновике — нажать «Попробовать ещё раз», когда связь вернётся |
| «Сессия устарела или нет прав редактора» | Токен не обновился (долго в фоне) или UID не в `editors`. Выйти и войти заново |
| В поиске все метки золотые | Не прогнан обновлённый `schema.sql`: старая `search_all` не отдаёт цвет |
| Фото не загружается: `mime type not supported` / `exceeded the maximum allowed size` | Бакет пропускает только `image/*` до 12 МБ — это страховка; приложение и так сжимает фото |
